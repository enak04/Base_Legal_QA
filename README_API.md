# Legal QA API

REST API service for the **HKG+PC+RL Legal Question Answering** framework.

Exposes the existing inference pipeline (Hierarchical Knowledge Graph → PPO RL reasoning → DSSM past-case retrieval → cross-encoder reranking → GPT-4o generation) as a standalone HTTP service that another backend can call.

## Prerequisites

1. **Python 3.10+**
2. **Trained model checkpoints** in the data directory (`HKG+PC+RL/Employment_Labour/actionable/` by default):
   - `rl_policy_model.pt` — run `python train_rl.py` to generate
   - `dssm_model.pt` — run `python train_dssm.py` to generate
   - `dssm_retrieval_index.pt` — generated by `train_dssm.py`
   - `node_embeddings.pt` — generated during RL training
3. **OpenAI API key** (for GPT-4o generation)

## Setup

```bash
# Install dependencies
pip install -r requirements.txt

# Configure environment variables
copy .env.example .env
# Edit .env and set OPENAI_API_KEY
```

## Running the Server

```bash
uvicorn api.app:app --host 0.0.0.0 --port 8000
```

The server loads all models once at startup and keeps them in memory.

## Endpoints

### `GET /health`

Health check.

**Response:**
```json
{"status": "ok"}
```

### `POST /predict`

Run legal QA inference for a single question.

**Request:**
```json
{
    "question": "My employer has not paid my salary for three months."
}
```

**Response:**
```json
{
    "question": "My employer has not paid my salary for three months.",
    "answer": "Under Section 4 of the Payment of Wages Act, 1936, wages must be paid before the 7th/10th of the following month...",
    "reasoning_chain": ["PWA_4", "IDA_25", "RPSR_34", "MHA_114"],
    "retrieved_cases": [
        {
            "question": "My company has not paid salary for 2 months...",
            "answer": "You can file a complaint with the Labour Commissioner..."
        }
    ]
}
```

**Error Responses:**

| Status | Meaning |
|:-------|:--------|
| 400    | Empty or missing question |
| 422    | Malformed request body |
| 500    | Inference or LLM error |
| 503    | Models not loaded (checkpoints missing) |

## Example Usage (curl)

```bash
# Health check
curl http://localhost:8000/health

# Predict
curl -X POST http://localhost:8000/predict \
  -H "Content-Type: application/json" \
  -d '{"question": "My employer has not paid my salary for three months."}'
```

## Example Usage (Python)

```python
import requests

resp = requests.post(
    "http://localhost:8000/predict",
    json={"question": "Can my landlord evict me without notice?"}
)
print(resp.json())
```

## Environment Variables

| Variable | Required | Default | Description |
|:---------|:---------|:--------|:------------|
| `OPENAI_API_KEY` | Yes | — | OpenAI API key for GPT-4o |
| `LLM_BACKEND` | No | `openai` | LLM backend: `openai`, `groq`, `ollama`, `hflocal` |
| `OPENAI_MODEL` | No | `gpt-4o` | OpenAI model name |
| `GROQ_API_KEY` | No | — | Groq API key (if using Groq backend) |
| `LEGAL_QA_DATA_DIR` | No | `HKG+PC+RL/Employment_Labour/actionable/` | Path to experiment data directory |

## Architecture

```
Website / Frontend
        │
        ▼
Main Application Backend
        │
        │ HTTP POST /predict
        ▼
┌──────────────────────┐
│    Legal QA API       │
│                       │
│  Seed Chain Discovery │ ← TF-IDF over KG nodes
│  PPO RL Reasoning     │ ← rl_policy_model.pt
│  DSSM Retrieval       │ ← dssm_model.pt
│  Cross-Encoder Rerank │ ← InLegalBERT
│  GPT-4o Generation    │ ← OpenAI API
└──────────────────────┘
```
